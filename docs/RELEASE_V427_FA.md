# نسخه ۴٫۲۷ — اصلاحات پل عملیاتی قدیمی

این بسته فقط بر پایه main/V4.26 است. شاخه رسمی آینده codex/canonical-v5-build است و استقرارهای اخیر Vercel از آن ساخته شده‌اند. این نسخه جایگزین V5 نیست و بدون تعیین نسخه واقعی Apps Script نباید روی محیط عملیاتی نصب شود.

## اصلاحات

- درخواست مستقیم و فاقد راز معتبر به Apps Script رد می‌شود.
- فایل api/telegram-webhook.js هدر secret_token تلگرام را بررسی کرده و درخواست را با راز مستقل به Apps Script می‌فرستد.
- تطبیق مالکیت دقیق است؛ نام قدیمی فقط در صورت انتساب یکتا پذیرفته می‌شود. شناسه صریح مالک وظیفه بر نام اولویت دارد.
- حساب غیرفعال/آرشیوشده اجازه نوشتن در CRM ندارد. غیرفعال‌سازی صریح تلاش می‌کند دسترسی مستقیم فایل را هم حذف کند؛ دسترسی ارثی از پوشه باید جداگانه بررسی شود.
- همگام‌سازی دوره‌ای با نشانگر ذخیره‌شده، بین کاربران فعال می‌چرخد.
- مشتری فاقد Customer ID به رکوردهای بدون شناسه دسترسی ندارد.
- checkReleaseReadinessV427 بدون تغییر داده، دسترسی و تنظیمات پایه را بررسی می‌کند.

## تنظیم هماهنگ وب‌هوک

در Apps Script Script Properties:

    TELEGRAM_RELAY_SECRET
    TELEGRAM_WEBHOOK_SECRET
    TELEGRAM_WEBHOOK_URL

در محیط Relay:

    TELEGRAM_RELAY_SECRET
    TELEGRAM_WEBHOOK_SECRET
    APPS_SCRIPT_WEB_APP_URL

رازها را خارج از Git تولید کنید. TELEGRAM_RELAY_SECRET حداقل ۳۲ نویسه و TELEGRAM_WEBHOOK_SECRET شامل ۳۲ تا ۲۵۶ نویسه مجاز A-Z/a-z/0-9/_/- باشد. مقدارهای متناظر دو محیط باید برابر باشند. TELEGRAM_WEBHOOK_URL آدرس HTTPS رله با مسیر /api/telegram-webhook و APPS_SCRIPT_WEB_APP_URL آدرس واقعی /exec است.

ابتدا از Apps Script و Spreadsheet نسخه پشتیبان بگیرید. رله را در پروژه/محیط آزمایشی مستقل مستقر کنید؛ تنظیمات ریشه این بسته را روی پروژه V5 با Root Directory=backend تحمیل نکنید. در کپی آزمایشی Apps Script کد را قرار دهید و WEB_APP_URL را به همان محیط وصل کنید. سپس checkReleaseReadinessV427 و setTelegramWebhook را اجرا کنید. setTelegramWebhook به‌جای حذف وب‌هوک، آن را جایگزین می‌کند و پیام‌های منتظر را حذف نمی‌کند. Endpoint رله باید برای Telegram قابل دسترسی باشد؛ صفحه ورود Vercel پاسخ معتبر وب‌هوک نیست.

آزمون عملی: درخواست فاقد راز رد شود؛ پیام و callback واقعی برسد؛ دو شرکت به داده هم دسترسی نداشته باشند؛ کاربر غیرفعال نتواند بنویسد؛ فضای کاری شماره ۲۱ و بعد از آن همگام شود. پیش از قبولی این آزمون‌ها انتشار عملیاتی انجام نشود.

برای بازگشت، کد Apps Script و رله و تنظیم وب‌هوک قبلی را هماهنگ بازیابی کنید. بازگشت به کد قدیمی مشکل وب‌هوک تأییدنشده را دوباره باز می‌کند.
