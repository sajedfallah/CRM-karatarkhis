- standardize on `لید جدید`

Do not keep two semantically identical states permanently.

## 5. V-002 — Task vocabulary differs between Sheet validation and Apps Script

Severity: **HIGH**

### Live Sheet validation — Priority

`تسک‌ها!I2:I2000`

Allowed:

- پایین
- متوسط
- بالا
- فوری

### Apps Script Task Wizard — Priority

Allowed:

- بالا
- متوسط
- پایین

Difference:

- Sheet allows `فوری`
- Apps Script Wizard does not

### Live Sheet validation — Status

`تسک‌ها!J2:J2000`

Allowed:

- جدید
- واگذار شده
- در حال انجام
- منتظر پاسخ
- منتظر مدیر
- انجام شده
- بسته شده
- لغو شده

### Apps Script Task Wizard — Status

Allowed:

- باز
- در حال انجام
- منتظر پاسخ
- انجام شد
- لغو شده

Conflicts include:

- `جدید` vs `باز`
- `انجام شده` vs `انجام شد`
- Sheet-only: `واگذار شده`, `منتظر مدیر`, `بسته شده`

### Risk

A Task created from Apps Script can use a status that the Sheet's strict validation does not recognize, and a Task edited in the Sheet can use states not represented by the Wizard.

This is a cross-interface state-machine drift and must be resolved before production readiness.

### Remediation requirement

Define one canonical Task enum and reuse it from:

- Apps Script Wizard
- Google Sheet validation
- Telegram formatting/actions
- Workspace views
- migration code
- tests

No automatic Production change was made because selecting the canonical state vocabulary is a business/workflow decision.

## 8. F-001 — Identifier/contact fields are stored as numbers

Severity: **MEDIUM**

Current examples include numeric storage for fields that should be treated as identifiers/text:

### مشتریان

- `شناسه ملی / کد ملی`
- `شماره ثبت`
- `کد اقتصادی`
- `موبایل`
- `تلفن`

### کارمندان

- `Telegram User ID`

### کارهای روزانه

- `Telegram Message ID`

### Risk

For identity/contact data, numeric storage can:

- drop leading zeroes
- permit scientific display in exports
- create inconsistent string comparisons
- create format drift across Sheets/API/Apps Script

Current exported mobile/Telegram values already appear in scientific numeric representation internally.

### Remediation requirement

Canonical ID/contact fields should be treated as text strings at ingestion boundaries. Existing values must be migrated carefully; formatting alone cannot reconstruct leading zeroes that were already lost.

No automatic conversion was made because the original semantic value cannot always be reconstructed safely.

## 9. F-002 — Exported dynamic formula representation is not suitable for offline regression

Severity: **MEDIUM**

Google Sheets dynamic formula results are exported into compatibility wrappers and expanded fallback cells.

Therefore tests that simply search an XLSX export for formula strings may report false incompatibilities.

### Required test policy

- Native Sheet API: formula/effective-value validation
- XLSX export: structure, formatting, validation, and portability check
- Apps Script tests: workflow/state behavior

These evidence classes must remain separate.
