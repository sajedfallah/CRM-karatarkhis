## Root cause

Production still showed the V4.10.0/V4.9.x sheet state (`LEAD_BATCH_SIZE=5`, static Ardavan desk), and the admin form checkboxes B6/B15 remained TRUE with blank result cells. The hidden `کارمندان` and `فهرست‌ها` sheets did not contain the submitted records, and System Log had no `ADMIN_FORM` entries. This is consistent with an older installable onEdit handler (for example `onCrmEditV493`) still being active. That handler does not call `handleAdminFormsEditV494_()`.

## Fix

- Adds `installMasterEditTriggerV4102_()` to remove stale CRM onEdit handlers and install exactly one `onCrmEditV410` trigger.
- Adds `processPendingAdminFormsV4102_()` so already-checked admin actions are processed once during setup instead of requiring re-entry.
- Adds `diagnoseAdminFormsV4102()` to verify the master trigger, stale handlers, current admin-form state, list insertion, and employee insertion.
- `setupV4102()` runs the full V4.10.1 audited migration/setup first, then repairs the master edit trigger, processes pending admin actions, and runs diagnostics.

## Deployment

1. Replace Apps Script source with the full Drive V4.10.2 file.
2. Preserve Script Properties.
3. Save.
4. Run `setupV4102()` once and approve permissions.
5. Run `diagnoseAdminFormsV4102()`.
6. Expected: `masterOnEditCount: 1`, `staleEditTriggers: []`, `listPresent: true`, `employeePresent: true`, `ok: true`.
7. Then run `diagnoseV4101()` to re-check the broader workbook audit.

Do not run legacy `installTriggers()`.
