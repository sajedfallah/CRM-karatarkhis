## Audit verdict

The external Gemini audit contained several valid findings, but its proposed replacement controller is not compatible as a drop-in replacement with the current V4.10.x architecture.

### Adopted / corrected
- Installable master onEdit trigger enforced; final handler is `onCrmEditV4103`.
- Admin form actions use `LockService.getScriptLock()` and unconditional checkbox reset in `finally`.
- Lead date fields are normalized to real Sheet Date serials during setup, direct edits, and hourly SLA processing.
- Dashboard overdue-lead formula is defensive for both serial and ISO-text values.
- Empty employee rows no longer retain FALSE checkbox values; registry is compacted.
- Employee insertion now searches for a real blank identity row instead of relying on `getLastRow()`.
- `بازرسی` is ensured under `فهرست‌ها > نوع مشتری`.
- Company profile formulas use bounded ranges instead of entire columns.
- Case finance ARRAYFORMULA columns G/H/I/L/M are repaired and stale spill blockers below row 2 are removed.
- Company reference list is synchronized non-destructively from leads/customers/tasks.
- Admin CRUD audit records include payload and execution duration in `System Log`.

### Not adopted as stated
- The trigger failure was not caused by a simple `onEdit` permission barrier. The production symptom was consistent with a stale installable handler (e.g. `onCrmEditV493`) that did not route admin forms.
- The exact Gemini `DATEVALUE` formula is invalid on blank/full-column inputs and was reproduced as `#VALUE!` in staging (`DATEVALUE parameter '' cannot be parsed`).
- Company names are not automatically renamed/merged based on similarity; this could merge distinct legal entities. Exact names are synchronized into the reference list, while canonical-ID/alias migration should be explicit.
- ARRAYFORMULA spill risk is only real when derived output cells are manually populated; normal case registration does not write to G/H/I/L/M. V4.10.3 hardens these columns without changing user-input columns.
- Gemini's standalone code redeclared global `CONFIG`, omitted current client portal/case-stage routing, referenced a non-existing `processClientAccessLink`, and did not preserve current Script Property mirroring/persistent-menu behaviors; it is therefore not used as a replacement codebase.

## Installation
1. Replace the Apps Script source with the full V4.10.3 Drive file.
2. Preserve Script Properties (`BOT_TOKEN`, `GROUP_CHAT_ID`, `SPREADSHEET_ID`, `WEB_APP_URL`, folder IDs).
3. Save and run `setupV4103()` once.
4. Approve permissions.
5. Run `diagnoseV4103()`.
6. Expected: `masterOnEditCount: 1`, `staleEditTriggers: []`, `ghostEmployeeCheckboxRows: []`, `nonSerialLeadDateCells: []`, `leadBatchSize: 10`, `inspectionCustomerTypePresent: true`, `ok: true`.
7. Do not run legacy `installTriggers()`.
